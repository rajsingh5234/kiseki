# 017: Continuous integration (CI) on GitHub Actions

- **Date:** 2026-11-23
- **Status:** Accepted

## Context

Lefthook checks staged files on each commit, but it can be skipped and runs only on our laptops. We need checks that always run, on a clean machine, for every push and pull request. Before deciding, we read the CI files of Vite, Vitest, Astro, Vue core, tRPC, Excalidraw, shadcn/ui and Turborepo.

## Choice

- **GitHub Actions**, in one workflow (`.github/workflows/ci.yml`), on every push to `main` and every pull request.
- **Three jobs, split by kind of check** (the Vite, Vitest and Astro pattern):
  - `lint`: format check, lint, typecheck;
  - `test`: tests with the 80% coverage minimum;
  - `audit`: `pnpm audit`, separate because GitHub's advisory list can change without our code changing.
- **Setup:** `pnpm/action-setup` (pnpm from `packageManager`) and `actions/setup-node` (Node from `.nvmrc`, pnpm store cached), then `pnpm install --frozen-lockfile`, so CI fails instead of changing an out-of-date lockfile.
- **Hardening** ([decision 004](004-supply-chain-security.md)):
  - no permissions by default (`permissions: {}`), `contents: read` per job;
  - every action pinned to a commit hash, with its version as a comment;
  - `persist-credentials: false` on checkout, so the access token doesn't stay on the machine;
  - a newer push cancels the older run of the same branch, and every job has a time limit.
- **Workflow security (added 2026-11-23):** zizmor scans the workflow files in its own workflow (`.github/workflows/zizmor.yml`), as Vite, Vitest and Astro do; findings go to the Security tab and a "Code scanning" check on pull requests. Both the action and zizmor's own version are pinned. actionlint is skipped for now (as in Vite and Astro): GitHub rejects broken workflow structure on push, and the recommended GitHub Actions VS Code extension catches typos while editing; reconsider when workflows get complex.
- **Dependency updates (added 2026-11-23):** Renovate (Mend's free GitHub app, installed on this repo only, "Scan and Alert" mode), as in Vite, Vitest, Astro, Vue core, tRPC and Nuxt; config in `.github/renovate.json5`. Weekly; all minor and patch updates in one pull request, each major on its own; versions at least a day old (matching pnpm); Node and pnpm in their own pull request (decision 003); lockfile refreshed weekly; action hashes kept pinned. Every update is merged by hand after CI passes, like most of those projects; auto-merging small dev-tool updates (tRPC's approach) is reconsidered once branch protection is on and the tests have grown. GitHub's Dependabot alerts are on (Dependabot's own pull requests off) so Renovate opens security fixes at once. Dependabot was the alternative: built into GitHub, but its pnpm 11/12 support only arrived in late 2026, with lockfile bugs reported.

## Alternatives

- **CircleCI, GitLab CI, Buildkite:** another account or machines to run, for no gain while the code lives on GitHub.
- **One job running every check:** simplest, but one ✓/✗ for everything, and slower as checks grow.
- **A matrix over operating systems and Node versions:** what libraries like Vite need; Kiseki runs on one server with one Node version.
- **`pnpm/setup` (pnpm and Node in one action, used by pnpm and Vite):** one action to trust instead of two, but 6 months old, three major versions in 4 months, and open bugs in its cache and lockfile handling. Revisit when it settles.
